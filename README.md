The code provides reference simulations for studying entrainment transitions in
oscillator populations under hybrid periodic forcing. Plotting scripts and final
figure artwork are not included.

## Physical problem

The paper considers a periodically forced Kuramoto population in which the
external forcing combines a constant component with a component that depends on
the instantaneous collective coherence. In the frame co-rotating with the drive,
the simulated dynamics are

```math
\frac{d\phi_i}{dt}
= (\omega_i-\Omega)
+ K R\sin(\Psi-\phi_i)
- L A_0\left[(1-\rho)+\rho R^\gamma\right]\sin\phi_i,
```

where

```math
R e^{i\Psi}=\frac{1}{N}\sum_{j=1}^{N}e^{i\phi_j}.
```

The hybrid ratio $\rho\in[0,1]$ interpolates between constant forcing
($\rho=0$) and fully collectivity-dependent forcing ($\rho=1$). Increasing
$\rho$ changes the entrainment transition from smooth and reversible to abrupt
and hysteretic. In the low-dimensional theory, this change is associated with a
cusp catastrophe: the locked-state self-consistency curve becomes S-shaped,
producing saddle-node bifurcations, bistability, and distinct forward and backward
transition thresholds. Simulations with Lorentzian, Gaussian, and bimodal natural
frequency distributions test the robustness of this mechanism.

## Numerical method

The code integrates the finite oscillator population with a fourth-order
Runge-Kutta method. Forward and backward parameter sweeps use adiabatic
continuation: the final phase state at one forcing value initializes the next.
Stationary observables are averaged after discarding a transient interval.

The public implementation runs on the CPU. Full-resolution configurations use the
paper parameters, normally $N=2000$, and are computationally expensive. Natural
frequencies are represented by deterministic distribution quantiles and initial
phases use fixed random seeds, making repeated runs directly comparable.

## Running the reference simulations

MATLAB R2021a or newer is required. No Parallel Computing Toolbox is needed.

The commands below run the refactored reference implementation. They do not
execute the archived original scripts.

Clone or download the repository, open MATLAB, and change to the `matlab`
directory:

```matlab
cd('path/to/hybrid-forcing-simulations/matlab');
list_studies;
```

To run every reference simulation with the full documented configurations:

```matlab
output_paths = run_all_studies('full');
```

To run one reference calculation independently, pass its registered identifier
to `run_study`. For example, the forward and backward forcing scans across hybrid
ratios are generated by

```matlab
[result, output_path] = run_study('hybrid-ratio-response', 'full');
```

The available simulations are:

| Paper result | Study identifier | Numerical quantity |
|---|---|---|
| Fig. 1 | `hybrid-ratio-response` | Forward and backward forcing scans across hybrid ratios |
| Fig. 2 | `stationary-detuning-map` | Stationary coherence over detuning and hybrid ratio |
| Fig. 3(a-c) | `detuning-continuation` | Forward and backward forcing maps across detuning |
| Fig. 3(d-f) | `stationary-hybrid-map` | Stationary coherence over forcing and hybrid ratio |
| Fig. 4 | `transition-boundaries` | Transition thresholds and hysteresis width |
| Fig. 5 | `phase-resolved-response` | Co-rotating phases, coherence, and collective frequency |
| Fig. 6(a-c) | `coupling-response` | Entrainment response for different coupling strengths |
| Fig. 6(d) | `frequency-locking` | Frequency-locking error over forcing and coupling |
| Fig. 7 | `distribution-robustness` | Gaussian and bimodal robustness tests |

The `transition-boundaries` workflow was reconstructed from the parameter values
reported in the manuscript because its exact final simulation generator was not
retained. This provenance distinction is stored with every result.

Each run writes a timestamped MAT file to `outputs/data/`. The saved `result`
structure contains the numerical arrays, the complete configuration, and
traceability metadata. The output directory is ignored by Git.

Because this repository contains a refactored reference implementation, these
runs are intended to reproduce the documented numerical procedures and qualitative
results rather than the exact archived data or final typeset figures. The full
parameter values are listed in [docs/PARAMETERS.md](docs/PARAMETERS.md), and the
correspondence between registered studies and manuscript results is documented in
[docs/MANUSCRIPT_TRACEABILITY.md](docs/MANUSCRIPT_TRACEABILITY.md).

## Code organization

The directory structure follows numerical responsibility rather than figure
number:

| Path | Purpose |
|---|---|
| `matlab/+hybrid/` | Complete oscillator solver, continuation, parameter grids, and MAT output |
| `matlab/+presets/` | Full parameter configurations for each physical study |
| `matlab/+studies/` | Study workflows and the descriptive study registry |
| `matlab/run_study.m` | Configure, execute, and save one registered simulation |
| `matlab/run_all_studies.m` | Execute all registered simulations |

The differential equation, its RK4 stages, and tail observables are kept together
in `hybrid.integrate_batch` so the numerical model can be read as one complete
unit. Higher-level scan workflows reuse that solver, while presets contain only
the parameters that distinguish one physical calculation from another. Further
details are given in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Validation

The configuration and simulation pipelines can be checked from MATLAB with

```matlab
cd('path/to/hybrid-forcing-simulations/tests');
run_configuration_tests;
run_smoke_tests;
```

These tests verify the registered parameters and numerical workflow. They do not
replace the full-resolution simulations used for comparison with the paper.
